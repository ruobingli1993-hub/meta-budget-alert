# M12 素材视觉解析工作流（闭环）

> 目标：**每一次生成 M11 / M12 时，新增素材都会被自动纳入解析，不依赖人工想起来才解析。**

## 现状问题（为什么补这环）

- `reconcile_assets` 在每次 M12 生成时自动执行：解析过的素材（文件指纹 SHA-256 一致）直接复用缓存；**没解析过的新素材只挂 pending、写进队列**，解析本身不会自动发生。
- 之前"解析"是显式动作：模型辅助核对素材后写结构化分析，再用 `record` 提交。没人提交，周报里新素材就一直是"待视觉核对"。
- 本工作流把"准备证据 → 模型解析 → 提交入库"接成闭环，并约定**每次跑周报时由 MainAgent 自动执行解析**。

## 闭环流程

```
跑 M12 / M11
   │
   ├─ 1. scan（自动）   reconcile_assets：解析过的复用缓存；新素材 → pending + 入队
   │                    （weekly_report_module_12.generate 内已内置）
   │
   ├─ 2. prepare（自动） prepare_assets：读队列，为每个 pending 任务准备可视证据
   │                    图片 → 素材文件本身；视频 → 已有关键帧（复用，不重抽），
   │                    缺帧才用 VLC 按时间点抽取（0/1/3/5/10/20/30/45/60s，最多8张代表帧）
   │                    输出 M12_visual_parse_input.json
   │
   ├─ 3. parse（MainAgent 执行） 读 M12_visual_parse_input.json，逐个 Read 证据文件，
   │                    按 8 段落结构（hook / core_promise / product_solution /
   │                    product_proof / trust_proof / offer / cta / content_gap）
   │                    + transcript 写结构化分析 JSON
   │
   └─ 4. record（自动） record_analysis：校验（status=complete、8段落齐全、指纹一致）
                        写入指纹缓存；下次 scan 自动复用，不再重复解析
```

## 每周动作（MainAgent 固定执行）

1. 生成 M12（`weekly_report_module_12.py`，自动 scan + prepare）
2. 生成 M11（`weekly_report_module_11.py --m12-payload <新M12_payload.json>`，封面自动同步）
3. **检查 `M12_visual_parse_input.json`**：若 `summary.tasks > 0`，逐个任务：
   - Read 证据文件（图片直接读；视频读关键帧，必要时核对原视频）
   - 写 `analysis.json`（8 段落 + transcript + source 注明看了哪些帧/文件）
   - `python tools/m12_visual_workflow.py record --queue <queue> --task-id <id> --analysis <analysis.json>`
4. 全部 record 后，**重跑 scan**（可选，把解析写回 payload 并重建 HTML）或在下一次生成时自动生效
5. 队列里 `source_missing` 的任务：保留表现数据，标记"待补充素材文件"，不删数据、不借用同名解析

## 硬规则（与用户已确认口径一致）

- **指纹认证**：只有本地文件 SHA-256 与缓存一致才复用解析；文件名永不认证解析。
- **缺源不伪造**：原素材文件缺失 → 挂"待解析 / 源缺失"，禁止按同名素材的解析冒充。
- **缺帧才抽**：已有帧目录一律复用；仅新视频且无任何帧时才抽取；抽帧结果写入素材自己的帧目录，后续直接复用。
- **豁免名单**（`VISUAL_ANALYSIS_EXEMPTIONS`）与动态目录广告不解析，标 not_applicable 并保留表现数据。

