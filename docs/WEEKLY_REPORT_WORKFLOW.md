# 周报生成工作流

## 输入与顺序

1. 确认报告周为周日至周六，核验 BI 与 Google 原始表的报告周及对比周日期覆盖；不擅自把空值当作零。
2. 按 M01–M12 顺序生成、校验并逐模块交付。失败模块标明具体缺口，不伪报完成，其余独立模块继续。
3. Meta 平台数据由现有只读接口获取；禁止通过周报流程修改广告、预算或状态。

## M09 Meta 国家数据（固定步骤）

- 在生成 M09 时从 Meta 只读 API 按 `country` breakdown 读取 QMDT—20240103、销售三部—新主页账户和 Jelenew+ 三个 Performance 账户；覆盖报告周、上周及图表需要的对比周。当前入口为 `weekly_report_module_09.py` 的 `fetch_country_weeks`／`build_data`。
- 用户无需每周导出或上传 `Meta_AI_国家*.xlsx`。该旧文件不存在不等于国家数据不可用，也不能因此跳过 Meta API 读取。
- 记录实际读取的账户、日期范围和数据源；核对国家汇总与同账户、同日期范围的平台总量。缺账户、缺天、API 错误或对账异常时标记待复核，保留已确认数据，不用零或旧周缓存补齐。
- 素材级国家拆分若在 M11 使用，同样读取 Meta 对应层级的只读国家数据，不以 M09 账户级国家占比推算素材表现。

## 交付门槛

- M04 的 Meta 和 Google 两张近四周表均须有 BI 订单量／BI AOS、平台订单量／平台 AOS 及 WoW。
- M12 每条入报的固定素材都必须有已完成的原素材视觉解析；待解析、缺源或解析指纹过期均不算完成。生成结果先检查 `metadata.visual_analysis`：只有 `pending=0` 且 `missing_source=0` 才能交付为正式 M12。不能用“下次补”代替本周解析。Meta 动态商品目录广告没有单一固定原素材，应单列为“不适用单素材解析”，保留其表现数据和明确标注的代表性缩略图，不得以缩略图冒充完整素材解析，也不计入待解析。
- M10/M11/M12 的素材首图必须从已核实的本地素材／关键帧生成并检查存在性；登记表有文件时先排查匹配与取帧流程，不直接要求用户重复提供。
- M12 “首投不足7天且花费<$100”按 Meta 广告实际上线时间（Ad `created_time`，同素材取最早上线广告）计算，不用首次花费日替代；上线日期已确认、距报告截止日不足7天且所选周期花费低于$100，才进入该分类。曝光量不作为门槛。用户确认的上线日期必须在回放重分类时保留，不得被快照范围校验重置；上线日期未确认、已满7天或花费达到$100的素材归“需要关注”。
- M12 本地版内容完整后，还须打包缩略图线上版、部署固定链接并验证页面周次与“查看拆解”入口；任一步未完成，明确报告“模块12线上同步未完成”。
